# Staged DSP access extension — offline preparation, October 21, 2026

**Offline only. No board staging, boot-v4 run, module load or live step.**
Implements the [extension design](../../hdmi-dsp-access-extension-design-2026-10-21.md)
on top of the [prefix that passed live](../2026-10-21-dsp-access-prefix/README.md).

## What was prepared

- **boot-v4** (`boot-v4-commands.json`, `boot-v4-manifest.json`): generated by
  `tools/hdmi/prepare-dsp-observe-boot.py --variant v2` from the same pinned
  FIT (`0877293b…`). Relative to boot-v3 it adds two guarded commands and
  changes the banner (`boot-v3-to-v4-commands.diff`): `fdt rm` of
  `allwinner,keep-tvcap-on` on the PPU node, and the
  `h713,dsp-observation-v2` marker. The offline reference DTB differs from
  boot-v3's by exactly those two edits (`boot-v3-to-v4-dt.diff`). The default
  `v1` output was regenerated and is byte-identical to boot-v3 (all four
  files). Still RAM-only: no environment save, media write, SPL, BL31 or proper change.
- **Module** `h713-hdmi-dsp-access-audit.ko` `39d2a2e9…`: steps 1–33 unchanged
  in operation and order; 34–40 read-only census; 41–82 domains, clocks,
  resets and TVFE words (`steps.json`). Extension steps are refused unless the
  booted DT has the v2 marker and no TVCAP retention flag. W=1 build against
  the exact 6.18.38 tree; the only warning is the known compiler 23.1.3 versus
  23.1.1 (`module-build.txt`). Vermagic `6.18.38 SMP mod_unload aarch64`.
- **Imports** (`module-imports.txt`): beyond the prefix's set, exactly
  `__clk_is_enabled`, `clk_prepare`, `clk_enable`, `clk_unprepare` (the inline
  error path of `clk_prepare_enable`), `__pm_runtime_resume`,
  `pm_runtime_enable`, `of_genpd_add_device`, `dev_pm_genpd_add_notifier`,
  `__root_device_register`, `reset_control_deassert`, `usleep_range_state`,
  `of_property_read_bool`, `param_array_ops` and `alt_cb_patch_nops`. There
  is no reset assert, clock disable, genpd removal or runtime-PM put: no
  restore path exists, by design.
- **Helper** `dsp-access-audit.py` `7ca50c19…`, schema
  `h713-dsp-access-ext-v1`: boot-v4 DT checks, the console/panic preflight,
  stage boundaries after steps 33, 40, 45, 53, 69, 74 and 81 that require a
  read-only `snapshot` (clock and genpd debugfs summaries) and then
  `--stage-ack`, and `release` refused after step 40.
- **Guard** `96f37655…`: unchanged and already installed on the board; the
  module name is unchanged, so it still converts reboot/kexec to poweroff.

## Offline checks

- `ext-tests.txt`: 16 tests pass. They cover every refusal (including the
  boot-v3 DT and the retention flag), a kernel without the extension, every
  stage boundary needing a snapshot and the exact ack, release through step 40
  only, all 82 steps ending without AudioTop, lost acknowledgments, failed
  load/step/release, C/Python step-name and clock-index parity, and TVFE
  word offsets matching the C table.
- Mutation checks (not committed as files): disabling the stage gate, the
  snapshot requirement, the release limit, the TVCAP-flag check or the v2
  marker check; renaming a C step; swapping a C clock index; changing the C
  release limit or a TVFE offset. Each made the suite fail.
- `guard-tests.txt` (3), `legacy-observe-tests.txt` (5) and
  `boot-prep-tests.txt` (3) still pass.

These establish offline consistency only. Nothing here shows that any
domain, clock or reset operation is safe on hardware, or where AudioTop sits.
`preparation.json` records the source, kernel-input and output hashes;
`sha256.json` covers this directory.
