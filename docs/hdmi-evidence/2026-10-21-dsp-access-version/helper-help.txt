usage: dsp-access-audit.py [-h] --bundle BUNDLE --expected-boot EXPECTED_BOOT
                           [--expected-step EXPECTED_STEP]
                           [--operation OPERATION] [--stage-ack STAGE_ACK]
                           {load,step,snapshot,status,release}

One explicit staged-access step per invocation; never run a stage loop. A
failed/uncertain operation consumes this boot. No reset or reboot.
AudioTop/DSP access is limited to steps 83-92, TVTOP routing to 93-104, lock-
word reads to 105-108, and the one-shot lock claim, 0x80ff version pair and
release to 109-119. The peer lock word is never written; no patch, graph or
selector write exists. Crossing a stage boundary needs a read-only `snapshot`
and then `--stage-ack <stage>`. From step 41 on, the only supported end is an
orderly poweroff with the module loaded; `release` is refused. This helper
must be staged with the guard and a pinned manifest.

positional arguments:
  {load,step,snapshot,status,release}

options:
  -h, --help            show this help message and exit
  --bundle BUNDLE
  --expected-boot EXPECTED_BOOT
  --expected-step EXPECTED_STEP
  --operation OPERATION
  --stage-ack STAGE_ACK
