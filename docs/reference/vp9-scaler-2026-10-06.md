# VP9 through the VE polyphase scaler (WP6, 2026-10-06)

**Result: VP9 scales on the VE while it decodes, as H.264 and HEVC already
did.** Kernel patch **0167** (`media-cedrus-scale-vp9-with-the-polyphase-scaler`)
admits VP9 to `cedrus_can_scale()`. `h713-play` now sends 8-bit VP9 that is
larger than its fit to **plane-ve** (`vavp9dec` with the VE scaler, then
`kmssink`), with the GPU idle. AV1 is the only codec left on the GPU above
the panel.

## The recipe, from two independent sources

VP9 runs on the H.265 engine (VE+0x500), and that engine's secondary output
is what feeds the TOP1 polyphase scaler at VE+0xf00.

| | stock, 4K VP9 → 1920x1080 | Jernej Skrabec, H6 VP9 P010 | 0167 |
| --- | --- | --- | --- |
| engine func_ctrl `+0x30` | `0x207` (bit 9 = secondary out) | `\|= BIT(9)` | `\|= BIT(9)`, read-modify-write after setup |
| secondary ctrl `+0x50` | 0 | 0 | 0 |
| secondary Y/C `+0x54/+0x58` | `0x000AC000` / `0x000ADFE0` (`addr >> 8`) | `addr >> 8` | `addr >> 8` |
| `+0x80` | 0 | not written | not written |
| VE top `0xcc`/`0xe8`/`0xec`, TOP1 | identical to stock's 4K HEVC case | — | the shared H.265 path |

Stock: `local/h713-lab/stock-capture-20261001/out/50-vp9-2160-2/ve.txt`, the one
snapshot of the two that fell inside a frame. Jernej: LibreELEC PR 11799 at
`ec0b334`, `projects/Allwinner/patches/linux/0413-media-cedrus-Add-VP9-P010-output-support.patch`
(and 0412 for the address helper).

Two differences from H.265, both in 0167:

- **No low-address register.** H.265's `+0x80` (LOW_ADDR) carries the low byte
  of the secondary chroma address, which is why H.265 needs only a 64-byte
  chroma base. VP9 has nothing there, so the base (`bytesperline * height`)
  must be 256-byte aligned. For VP9 the scaled capture's pitch is widened just
  enough: `ALIGN(pitch, max(32, 256 >> ctz(height)))`. A 1280 pitch, or any
  height that is a multiple of 8, is unchanged; 854x478 gets 896 instead of 864.
- **References are the reconstructions.** `cedrus_vp9_align()` derives the
  reference pitch field from the capture pitch. While scaling it must use the
  full-size reconstruction's pitch.

## Verification

All on the bench board with sunxi-cedrus.ko md5 `ab1765ba5e542a15b6b28484b2aae193`.

**Headless scaler suite** (`tools/video/cedrus-scaler-check.py`, VP9 cases
added; `--only vp9` runs them alone). Full run: **79 captures PASS, no kernel
faults**, with every H.264/HEVC/Main10 score unchanged. Before the module was
swapped, the VP9 cases failed on the old one (capture forced to 1280x720, no
dump), so they can fail.

| VP9 case | Y / U / V dB |
| --- | --- |
| v04 720p → 640x360 (format and compose APIs byte-identical) | 55.43 / 50.13 / 43.62 |
| v04 → 640x180, asymmetric | 47.88 / 44.73 / 38.29 |
| v04 → 854x478 (pitch widened to 896) | 43.00 / 38.22 / 35.69 |
| v11 1080p mandel → 960x540 | 51.74 / 49.36 / 48.95 |
| 1080p → 1280x720, key frame / P-frame 45 | 44.91 / 44.84 Y |
| scope 1920x800 → 1280x534, P-frame 20 | 44.07 / 41.27 / 36.46 |
| 4K → 1280x720, P-frame 8 | 41.21 / 37.27 / 32.14 |
| VP9 1080p and H.264 854x478 at once | both pass |
| v02, v03, v04, v07, v09, v10 (350x286), v11 unscaled | 99 (bit-exact) |

H.265's scaler scored 55.45 at 2x and 47.85 at 2x/4x; VP9's 55.43 and 47.88
are the same block. The lowest score, v10 at 174x142 (33.31 dB), is the
content: the same picture re-encoded as H.264 scores 33.66 through the H.264
path, the error sits on the hard horizontal edges, and the best alignment
offset is (0, 0).

**Bit-exact regression, GStreamer** (`vp9-gate.sh`, `v4l2slvp9dec` against
libvpx): v01–v12 all bit-exact, with VE IRQs ≥ frames. v11 (1080p) was
checked by streaming both decodes through md5, because two raw copies (2 ×
280 MB) do not fit the board's tmpfs. v13 (resize) is refused by design (0143).

**The real path, no LD_PRELOAD probe.** `vavp9dec` with `V4L2_REQUEST_SCALE`,
through `gst-plane-play` onto the video plane:

| clip | rendered / dropped | VE IRQ | GPU IRQ | IOMMU IRQ |
| --- | --- | --- | --- | --- |
| 1080p, 10 s → 1280x720 (video-plane fb id changes 51 → 45 → 52) | 300 / 0 | +300 | 0 | 0 |
| scope 1920x800 → 1280x534 | 30 / 0 | +30 | 0 | 0 |
| 4K, 5 s → 1280x720, via `h713-play` | 150 / 0 | +150 | 0 | 0 |

**Routing.** `h713-play` asks cedrus: with VP9 on a fresh context's OUTPUT
queue, `VIDIOC_ENUM_FRAMESIZES` offers NV12 as STEPWISE only where the scaler
is admitted. A/B on the same boot: old module → `gpu ("this kernel's VE does
not scale VP9")`, 0167 → `plane-ve`.

Not covered: an operator look at the glass (only the plane's fb id, drops and
IRQs were checked, not the picture), and VP9 with audio through `h713-play`.
