## The five AV1 hardware rules (do not regress these)

Each one wedged or stalled the SoC before it was understood. Details in the
reference doc; the code is `tools/re/av1/driver/sunxi_h713_av1_hw.c`.

1. **Release reset_av1 with the bus/MBUS clocks running.** hantro_probe
   deasserts it with them only prepared; the variant's init enables them
   (reset held) and keeps them on. Unclocked release = the core stalls on its
   first transfer and stays stuck until a power cycle ("poison").
2. **The IRQ (SPI 107) is pending at boot.** Request `IRQF_NO_AUTOEN`, arm per
   frame, disarm in the handler/reset.
3. **Never write image words 0 and 1.** Write 291..2 top-down, start held
   back, `wmb()`, start alone. Never write while the start bit is set.
4. **Bit 9275 is `allow_warped_motion`**, absent from the vendor's printer and
   so from the generated field table; defined by hand in `sunxi_h713_av1_gen.c`.
5. **Multi-tile needs `vert_filt_read/write_base`** (one buffer,
   `ALIGN_4K(ceil(h/64)*0xa00)`, allocated fixed at 4K size).

Also: PLL_VE ≤ 432 MHz (0144 sets cedrus's H713 rate; the AV1 variant
refuses to probe above it). PLL/clock registers: read the live value, change
one field.

## Remaining work

1. **Which register combination hangs the AV1 core** on inconsistent headers.
   The client-side gate in libva 0016 closes the known path; the kernel should
   not depend on it. Evidence and method are in the reference doc; the trace
   now pauses 50 ms per frame so the fatal image survives. Each attempt may
   cost a power cycle.
2. **Mid-stream resolution change through VA-API** (all codecs): `S_FMT` is
   refused while old surfaces exist. Proposed fix: `V4L2_MEMORY_DMABUF` capture
   from a dma-heap. Inter-frame resize (VP9 `v13`, AV1 reference scaling) would
   additionally need the AV1 core's unused `lu/cb_stride` registers; cedrus
   refuses such frames now.
3. **10-bit AV1** is refused (NV12 only). 10-bit AV1 content is common, and the
   core has `secondary_output_hbd`; worth one experiment on whether it can emit
   8-bit NV12 from a 10-bit stream, as cedrus does for HEVC Main10.
4. VP9 profile 2 (10-bit) is not implemented in cedrus.
5. `tools/video` hygiene: `va-decode-test.sh` leaves ~500 MB in
   `/var/tmp/va-out`, which fills the root filesystem and makes the next gates
   fail with "No space left" -- clear it between runs.

## If something breaks

- **The board wedges** (network gone): power cycle (USB unplugged first). If
  it happens at boot, restore the blacklist from `/root/av1/` via a backup FIT
  (`docs/flash.md`, "Recovering from a kernel that hangs at probe").
- **Every decode stalls after one failure**: the core is poisoned (a stuck
  transaction). Only a power cycle clears it; do not keep testing.
- **Output wrong but no errors**: diff the image (enable
  `hantro_vpu.h713_av1_trace=1` for a per-frame register dump) against the
  rig's for the same frame, *including unnamed bits*; then isolate features
  with libaom-encoded variants (`-aom-params …`), as in the reference doc.
- **Bring-up replay**: the 0141 probe module still matches the node but no
  longer autoloads. `rmmod hantro_vpu; modprobe sunxi_h713_av1_probe`, then the
  debugfs replay (`/sys/kernel/debug/h713-av1/`) runs vendor packages
  (`tools/re/av1/mkreplay.py`).
