## The five AV1 hardware rules (do not regress these)

Each one wedged or stalled the SoC before it was understood. Details in the
reference doc; the code is `tools/re/av1/driver/sunxi_h713_av1_hw.c`.

1. **Release reset_av1 with the bus/MBUS clocks running.** hantro_probe
   deasserts it with them only prepared; the variant's init enables them
   (reset held) and keeps them on. Unclocked release = the core stalls on its
   first transfer and stays stuck until a power cycle ("poison").
2. **The IRQ (SPI 107) is pending at boot.** Request `IRQF_NO_AUTOEN`, arm per
   frame, disarm in the handler/reset.
3. **Never write image words 0 and 1.** Write 291..2 top-down, start held
   back, `wmb()`, start alone. Never write while the start bit is set.
4. **Bit 9275 is `allow_warped_motion`**, absent from the vendor's printer and
   so from the generated field table; defined by hand in `sunxi_h713_av1_gen.c`.
5. **Multi-tile needs `vert_filt_read/write_base`** (one buffer,
   `ALIGN_4K(ceil(h/64)*0xa00)`, allocated fixed at 4K size).

Also: PLL_VE ≤ 432 MHz (0144 sets cedrus's H713 rate; the AV1 variant
refuses to probe above it). PLL/clock registers: read the live value, change
one field.

## Verification: how to run it

### Host: the AV1 generator gate (no board needed)

```bash
tools/re/av1/rig/gate.sh local/h713-lab/av1-work/gatework /home/chris/Projects/h713/local/h713-lab/av1-work/stock.ivf
```

Runs the vendor library in emulation (cached per clip) and the rig on 11
clips, comparing every named field, **every unnamed bit**, every buffer
address the vendor sets (fails if the rig leaves one at 0), and the
CPU-written buffers byte for byte. Must print `gate: 47 frame(s), PASS`. Pass
the stock clip by **absolute path** (a relative one silently drops it:
`gate: 37`). Re-run after any change to `sunxi_h713_av1_gen.c`.

### Board: AV1 (`tools/video/av1-gate.sh`)

Clips, libdav1d references (`*.ivf.framemd5`) and the gate are in
`/root/av1` (+ `/root/av1/iso`). The runner is `/root/av1/t-full.sh`
(single-tile first, then the reference-MV-off clips, multi-tile last). Every
line must say `PASS`, `frames exact N/N`, and `av1_irq` ≥ frames.

Host copies: `local/h713-lab/av1-work/` (gitignored; the scratchpad gets
wiped, so keep test data here). Regenerate a reference with
`ffmpeg -c:v libdav1d -i X.ivf -pix_fmt yuv420p -f framemd5 X.ivf.framemd5`.

`local/h713-lab/test-media/av1a-720p30-testsrc2-30s.mp4`

## Remaining AV1 work (suggested order)

1. **Long-clip soak.** Only ≤15-frame clips have run. Decode the full 30 s
   stock clip (`av1a-720p30-testsrc2-30s.mp4`, via `qtdemux ! av1parse`), then
   a longer real-content AV1 stream, then a loop of several minutes. Watch
   dmesg for `decode failed`, `core still busy`, `interrupt without a cause`,
   watchdog timeouts; check memory is stable (per-slot buffers grow only).
2. **4K on the board.** The rig gate covers 3840x2160 (the fixed buffers are
   sized for it) but it has never run on the hardware. Watch CMA/IOMMU memory:
   16 slots × ~21 MB at 4K if all slots fill.
3. **Resolution change mid-stream** (new sequence header): slot buffers grow
   on demand but have not been exercised.
4. **Seek / flush**: stop/start streaming, `gst-launch … seek`; the generator
   state resets per stream (`dec_init`), untested with mid-stream seeks.
5. **Concurrency with cedrus**: AV1 and H.264/VP9 decoding at the same time.
   They share the VE clock/reset via the device link; never tested together.
6. **10-bit output.** The core has `secondary_output_hbd`; the generator sets
   it for 10-bit streams, but the capture format list is NV12 only, so 10-bit
   sequences are refused. Needs a P010 (or similar) format and a check of the
   hardware's HBD layout. (Cedrus decided against 10-bit output on this 8-bit
   panel; weigh that before spending time here.)
7. **Playback on the panel**: mpv/GStreamer to the display (the VP9/H.264
   path uses `vo=drm` / DECD); AV1 has only been decoded to files.
8. **Cosmetics / upstreaming**: the deferred-probe message; split 0145 into
   hantro-core and variant patches; DT binding document for
   `allwinner,sun50i-h713-av1` and `allwinner,video-engine`.
9. **Film grain / bit depth / tiles beyond what was tested**: film grain on
   inter frames with `update_grain=0`, 4x4+ tiles, multiple tile groups per
   frame (the tile-start logic assumes one group).

Remaining VP9 work: a **VA-API backend** (libva-v4l2-request) so mpv can use
it; VP9 profile 2 (10-bit) is not implemented.

## If something breaks

- **The board wedges** (network gone): power cycle (USB unplugged first). If
  it happens at boot, restore the blacklist from `/root/av1/` via a backup FIT
  (`docs/flash.md`, "Recovering from a kernel that hangs at probe").
- **Every decode stalls after one failure**: the core is poisoned (a stuck
  transaction). Only a power cycle clears it; do not keep testing.
- **Output wrong but no errors**: diff the image (enable
  `hantro_vpu.h713_av1_trace=1` for a per-frame register dump) against the
  rig's for the same frame, *including unnamed bits*; then isolate features
  with libaom-encoded variants (`-aom-params …`), as in the reference doc.
- **Bring-up replay**: the 0141 probe module still matches the node but no
  longer autoloads. `rmmod hantro_vpu; modprobe sunxi_h713_av1_probe`, then the
  debugfs replay (`/sys/kernel/debug/h713-av1/`) runs vendor packages
  (`tools/re/av1/mkreplay.py`).
